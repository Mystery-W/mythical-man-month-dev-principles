# 来源与取舍

## 证据与来源层次

本技能依据用户提供的《人月神话（二十周年纪念版）》中文 EPUB、在本次对话中完成的全书读书笔记，以及用户于2026年11月7日提供的个人开发经验文本。该经验文本包含2026年11月3日的协作约定记录；它是用户提供的经验材料，不是对现有机器、项目或配置的实时检查结果。

原书：Frederick P. Brooks, Jr., *The Mythical Man-Month: Essays on Software Engineering*，二十周年纪念版。以章节和小节定位，不补造本中文 EPUB 未能充分确认的译者、ISBN和纸本页码。技能自包含，不要求另一台机器具有原附件或此前读书笔记。

区分三个层次：

1. **书中论述：** 产品化、概念完整性、协调成本、受控集成、文档、原型与增量，以及作者后期修正。
2. **从书中转化的工程实践：** 个体开发的时间跨度、风险驱动的探索、跨电脑验收、证据分级等；属于应用，不声称是原文规定。
3. **个人约定：** Git 格式、删除确认、Python 环境、沟通偏好等；本书没有给出这些工具级规则，不把“不曾讨论”误当作“反对”。

对于工程观点与原经验的实质冲突，采用本书在二十周年版中的完整、后期立场。个人授权、安全边界和当前项目明确要求仍需遵守，不能凭书中一般观点自行取消。

## 阅读本书时必须保留的修正

- 第11章“为舍弃而计划”应与第19章“没有构建舍弃原型”“增量开发模型更佳”合读。学习不可避免，不等于必须把整个系统做完再丢弃。
- 第7章的全面共享讨论应与第19章“关于信息隐藏，Parnas是正确的，我是错误的”合读。接口语义需要共享，调用者不应依赖全部内部实现。
- 第2章 Brooks 法则应与第19章关于人员与工期研究的讨论合读。加人有协调和培训成本，结果仍取决于阶段与工作可分性。
- 第16章“没有银弹”有单一进展、十年、数量级等论断边界；第17章继续讨论复用、质量与建模。它不能自动证明今天某个工具有效或无效。
- 第1章的三倍、九倍，第2章的工时比例，第8章的规模指数等，是相应历史背景中的判断，不用于机械报价、人员评级或验收门槛。

用户提供 EPUB 的封面简介混入其他主题，部分公式、语句和图示存在疑点。本技能使用正文主要论证与后期修正，不从可疑排印推导新规则。书中的工程经验也不能代替具体项目证据。
