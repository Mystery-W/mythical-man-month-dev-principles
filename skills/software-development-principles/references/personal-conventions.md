# 个人协作约定

仅在为本用户实际操作相关项目、文件或环境时应用。用户当前明确指示和目标仓库约定优先；不要把这里的偏好扩展成所有程序员的通用规范。提醒开发者的工程原则与约束代理执行权限是两件事。

## 操作与授权

- 已授权的常规实现细节主动完成，不因技能增加重复确认。对用户目标负责，但“做到最好”不扩大任务范围、费用或外部动作权限。
- 根据用户提供的删除约定：实际删除文件、目录、临时文件、缓存或插件数据前，说明准确范围及误删后果并取得明确同意。已明确批准的同一动作不循环确认；范围或后果变化再处理。先核对绝对路径，递归删除尤其明确范围。正常编辑中的代码行删减、重构和改写不属于这一删除确认流程。
- 当前无明确要求时不主动 commit 或 push；已有明确授权时不把同一动作重复送审。执行前说明操作范围，确认仓库、分支与远程。不自行改写已推送的共享历史，不绕过 hooks。对文件恢复和外部数据不要因 Git 存在就作无依据的保证。
- 对真实的凭证泄露、数据丢失或持续影响及时告知；不要为了“先修好再汇报”掩盖状态。第三方工具的安全或隐私取舍应围绕实际数据流与动作说明。

## 版本维护提醒

用户曾在大型软件上多轮修改而缺少分支维护，造成损失，希望获得主动提醒。在长期项目、跨多个会话的开发或大改前，检查当前分支、工作区和近期提交；不要仅因最近提交较早就推断项目已经失控。

有意义的提醒时机包括：完成一个可交付批次但未形成检查点；跨模块重构；数据格式、配置结构或重要依赖变化；即将大改；大量未提交工作或难以追溯的多轮修改。

原经验中的“3个目录、10个文件、10轮修改”仅为关注信号。少量文件也可能很危险，许多机械变更也可能很简单；以改动含义、恢复能力和现有证据决定提醒。

同批次通常提醒一次。用户已决定某阶段暂不存档时尊重该决定，在新的风险或里程碑出现时再提醒。提示应简短，给出建议分支、原子提交拆分、是否需要发布标签及相关变更说明；不要自动执行一整套分支—推送—打标签流程。

分支名遵守当前项目及运行环境规范；无其他约定且由 Codex 创建时默认使用 `codex/主题`。普通工作提交不必发版；发布或重要里程碑再决定标签。版本号按项目的兼容性约定确定，避免仅凭改动大小自动升级。

## 提交与文档偏好

- 提交前检查状态与差异，明确暂存范围，不无差别暂存整个工作区。不包含凭证、意外产物、无关临时文件或他人未完成改动。
- 提交尽量表达一个可解释的变化；不要机械拆成彼此不能理解的碎片。格式化、依赖变化等与功能无关时分开；同一行为需要的文档和验证应一起保留。
- 仓库规范优先。没有规范时，用户偏好 Conventional Commits：`类型(范围): 中文摘要 (english summary)`，正文可用“中文：”“English:”记录原因、影响与验证。标题尽量简短；若双语与长度冲突，将英文放入正文，不为格式牺牲清楚表达。
- 共享、集成及发布基线达到其约定检查。未验证的临时保存必须说明状态，不能宣称已通过。必要的 CHANGELOG 在发布前完整反映变更，不要求每个小编辑都增加日志条目。
- 用户偏好详细、可维护的注释和文档。模块、类、函数及关键步骤解释职责、输入输出、异常与设计理由；避免复制代码含义、无关背景或重复过时说明。重要决定可以记录在 ADR 或现有设计材料中，小修改用相称的记录。

## Windows 与 Python 环境

- 主要使用 Python 3.10 或更高版本，Windows 命令优先 PowerShell 或 cmd；代码使用 `pathlib.Path`、明确编码和类型注解，照顾中文、空格和 Windows 路径。可执行主程序采用 `if __name__ == "__main__": main()`。
- 开发前按需要检查现有环境；已知通用环境包括 NLP、SpeechProcessing、CV、Office。名字只是线索，实际解释器与包版本才是依据。选定后记录解释器、版本和关键依赖，后续命令保持一致。
- 不默认修改 base，不随意升级、降级或卸载共享环境的库。若必须修改已有 Conda 大环境，遵守用户要求：先说明风险，并取得两次确认后再给出最终修改命令。只读盘点或运行已有脚本不属于修改环境。
- 现有环境满足兼容、稳定与复现要求时优先复用；有必要的新环境应说明隔离原因和代价，不能只因为开了新项目就创建。运行与打包所需依赖应有项目自己的记录，不能依赖本机隐含状态。
- 模型与缓存位置需检查而非硬编码。原经验提及 D、E 盘与 `D:\hf_cache`，这些是历史线索，不保证现在仍成立。下载前在相关已知位置确认是否已有所需版本，不盲扫所有磁盘。复用缓存要检查适用性；迁移、联接或更改全局变量按具体任务处理。
- 批处理具备与任务相称的日志、错误处理、统计和输出位置说明；面向 Excel 的 CSV 优先 `utf-8-sig`。默认不覆盖原始数据，危险操作优先预览或保留可恢复副本。
- 新程序以可分发或可迁移到浏览器为长期方向；当前迭代可以小，但不让关键路径、环境和核心业务依赖不可搬迁的偶然条件。长期方向不代表每个脚本立即实现两套前端与全部平台支持。

## 连续工作与交接

在主题切换、上下文难以维持或需要独立调查时，可以建议拆分工作。先留下目标、位置、版本与工作区状态、已验证范围、已知问题和下一步。不能将“需要新会话”当作无限延后当前交付的理由。新建会话、提交或其他外部动作遵守实际授权。
